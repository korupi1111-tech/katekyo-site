# katekyo-site: Agent Guide

## Project overview

- This is a Vite + React + TypeScript site for `korupiyo`, a family-tutor matching and education-record platform.
- The active application entry point is `src/main.tsx`, which renders `src/App.tsx`.
- `App.tsx` contains the current page switching and the primary home, search, ranking, rank-system, login, and footer UI.
- Information, pricing, campaign, legal-guide, and profile-guide pages live in `src/components/InformationPages.tsx`.

## Commands

Run these from the repository root.

```powershell
npm run dev
npm run build
npm run lint
```

- `npm run build` is required after UI or TypeScript changes.
- The repository contains older, unused source files. A full lint may report existing issues in those legacy files; do not change unrelated legacy code merely to silence warnings.

## Where to edit

- Global site styles: `src/index.css`
- Trust-oriented visual layer: `src/trust-design.css`
- Campaign and pricing-promotion layouts: `src/campaign-layout.css`
- Header and footer refinements: `src/header.css`, `src/footer.css`
- Information and guide page styles: `src/information-pages.css`
- Rank-system page styles: `src/rank-system.css`, `src/rank-intro.css`
- Static images: `public/`

Do not edit generated build output in `dist/`. It is regenerated by `npm run build` and excluded from Git.

## Product and design principles

- Preserve the Japanese copy supplied by the site owner unless the request explicitly changes it.
- Keep the site professional and reassuring for students, parents, and teachers. Favor clear hierarchy, restrained color, readable text, and evidence-based presentation over app-like or playful decoration.
- The rank system represents verified lessons, evaluations, continuity, profile consistency, and reliability. Do not overstate what a rank guarantees.
- Do not implement client-side-only password gates as a form of access control. Use deployment or hosting access protection for limited release.

## Navigation

- Page navigation is local state in `src/App.tsx`, not URL routing.
- Use the existing `Page` union and `setPage`/`move` helpers when adding a destination.
- Keep navigation transitions immediate; do not reintroduce smooth whole-page scrolling.

## Git workflow

- Inspect `git status` before committing.
- Keep commits scoped to the requested change and use a concise imperative message.
- Run `npm run build` before committing UI work.
- Push approved changes to the configured `origin/main` repository after a successful commit.
- Never commit credentials, API keys, or local environment files. Keep `node_modules/` and `dist/` excluded.
